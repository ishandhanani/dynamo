# lib/preprocessor

`dynamo-preprocessor` owns the two pipeline stages around the engine. The preprocessor (crate root, `OpenAIPreprocessor`) turns an API request into the internal `PreprocessedRequest`: prompt formatting (`prompt`), tokenization, tool choice and structural tags (`tool_choice`, `structural_tag`), media loading and decoding (`media`), multimodal routing info (`mm_routing`), speculative prefill; and it turns the engine output stream back into API responses. The detokenizer (`backend`) holds the `Backend` operator, its `Decoder`, and the `ExecutionContext` alias. It transforms requests and response streams; it discovers no workers, routes nothing and serves no HTTP.

- Depends on (Dynamo crates): `dynamo-runtime`, `dynamo-frontend-protocols`, `dynamo-model-card`, `dynamo-telemetry` (request trace), `dynamo-memory` (RDMA media transfer), `dynamo-http-server` (the request metrics handle), `dynamo-kv-hashing` and `dynamo-kv-events` (multimodal block hashes), and the published `dynamo-protocols`, `dynamo-parsers`, `dynamo-parsers-v2`, `dynamo-renderer`, `dynamo-tokenizers`.
- Must not depend on: `dynamo-llm` or any crate above it. Discovery, the router code and the HTTP and gRPC services call into this crate; state they own is passed in as arguments, not imported.
- Request and response fields cross this crate. Before changing preprocessing, validation or response projection, read the [protocol field handling contract](../../docs/fern/pages/developer-guide/knowledge-base/modular-components/frontend/protocol-field-handling.md). `PREPROCESSOR_CASES.md` records the per-parser decisions; walk it when adding a parser.
- Hosts import this crate directly; `dynamo-llm` does not re-export it.
- Features: `mm-routing` (per-image token counts for multimodal-aware KV routing) and `media-ffmpeg` (frontend video decoding, needs the FFmpeg libraries); `dynamo-llm` forwards both, and the vLLM and SGLang sidecars forward `mm-routing` themselves. `testing` exports `test_fixtures` for `dynamo-llm`'s HTTP tests; `testing-nixl` compiles the media tests that need NIXL.
- Tests and benches read fixtures under `lib/llm/tests/data`. Tests that set process environment re-run themselves in a child process selected by test path, so renaming a test module means updating that path string.
- Check: `cargo test -p dynamo-preprocessor`, `cargo check -p dynamo-preprocessor --all-targets --features mm-routing`, and `cargo tree -p dynamo-preprocessor | grep dynamo-llm` must print nothing.
