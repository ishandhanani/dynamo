# lib/pool-relay

`dynamo-pool-relay` is the Pool Relay: one process per cluster that follows the workers of its routing pools and publishes what a global router needs to route across clusters. `PoolRelay` (`host`) supervises one actor per serving endpoint (`actor`: exact rank ownership and the endpoint-local CKF pool), projects discovery into membership and pool identity (`discovery`, `resolution`, `identity`, `pool_registry`), serving readiness and topology (`topology`), worker and scheduler load (`load`) and frontend serving load (`serving_load`), registers its routing pools with Global Discovery (`routing_pool`), and serves all of it through the transport-neutral publication source (`publication`) and its gRPC adapter (`wan::grpc`, protocol in `wan/grpc/protocol/relay.proto`). Read [`src/docs/architecture.md`](src/docs/architecture.md) for module ownership and the recovery invariants, and [`src/docs/grpc-contract.md`](src/docs/grpc-contract.md) before changing anything a subscriber can observe.

- Depends on (Dynamo crates): `dynamo-sync` (KV index ingest and recovery, worker load, the serving-load subjects and cadence), `dynamo-runtime`, `dynamo-model-card` (cards and the serving-readiness evaluator), `dynamo-kv-indexer`, `dynamo-kv-events`, `dynamo-kv-hashing`, `dynamo-slot-tracker`, `dynamo-router-protocol`, `dynamo-global-common`, `dynamo-global-discovery-client`, `dynamo-global-view-broadcaster`, and `dynamo-http-server` (only for the frontend load frame types it defines).
- Must not depend on: `dynamo-llm`, `dynamo-discovery`, `dynamo-router-host`, `dynamo-preprocessor`, or any crate above them. The Relay evaluates discovery on its own; it shares the readiness evaluator with the model catalog through `dynamo-model-card`, not through the catalog.
- Hosts import this crate directly (`dynamo-global-frontend` for the protocol, the Python bindings for `PoolRelay`); `dynamo-llm` does not depend on it or re-export it.
- The relay protocol, its frame sizes, the CBI1 encoding, pool identity and the event-plane subjects it reads are contracts with global routers, frontends and workers. A refactor must not change them, nor log message text, metric names or env vars.
- Log targets are `dynamo_pool_relay::...`.
- Features: `ckf-diagnostics` (pull-only stats and snapshots; the Python bindings forward theirs here, and it turns on `dynamo-sync/ckf-diagnostics`).
- `build.rs` compiles `src/wan/grpc/protocol/relay.proto` and writes the descriptor set the reflection service serves.
- Some tests start an in-memory distributed runtime and bind local ports; rerun a failing one alone before treating it as a regression.
- Check: `cargo test -p dynamo-pool-relay`, `cargo check -p dynamo-pool-relay --all-targets --features ckf-diagnostics`, and `cargo tree -p dynamo-pool-relay | grep -E 'dynamo-(llm|discovery) '` must print nothing.
