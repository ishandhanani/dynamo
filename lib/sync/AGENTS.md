# lib/sync

`dynamo-sync` keeps a router's view of its workers up to date. It owns KV index ingest, recovery and the remote indexer (`indexer`); active-sequence replica sync between routers (`sequence`); worker load (`load`: the `ActiveLoad` message and its subscription, `KvWorkerMonitor` with its busy thresholds, `RoutingLoadContext`, and the vocabulary of the serving-load streams a Pool Relay aggregates: the scheduler-load and frontend-load subjects, their cadence and the `DYN_SERVING_LOAD_PUBLISH` flag); KV event-source membership and the vocabulary the KV state agents share with the index (`membership`); the watch of per-worker runtime configs (`runtime_configs`); the Prometheus metrics of all of these (`metrics`); and the direct-ZMQ subscription the sync channels share (`direct_zmq_fan_in`, `direct_zmq_sub_pool`). It selects no worker, books nothing and dispatches nothing.

- Depends on (Dynamo crates): `dynamo-runtime`; the router crates `dynamo-kv-indexer`, `dynamo-kv-events`, `dynamo-kv-hashing`, `dynamo-slot-tracker`, `dynamo-scheduler`, `dynamo-router-protocol` and `dynamo-kv-router` (router configuration and the worker inputs a policy reads); `dynamo-model-card`, `dynamo-frontend-protocols`, `dynamo-http-server` (the per-worker latency gauges the worker monitor clears) and `dynamo-tokens`.
- Must not depend on: `dynamo-llm`, `dynamo-preprocessor`, or any crate above them. The router host (`dynamo-router-host`, `lib/router-host`), the model catalog (`dynamo-discovery`, `lib/discovery`), the worker-side publisher (`dynamo-backend-common`), the KV state agent (`dynamo-kv-state-agent`, `lib/kv-state-agent`) and the Pool Relay call into this crate; what it needs from them is passed in as arguments, as with the router-mode selectors of the remote indexer.
- Hosts import this crate directly; `dynamo-llm` does not re-export it.
- The recovery client that queries a worker's local index is here (`indexer/recovery/worker_query.rs`). The endpoint the worker serves is worker-side code: `dynamo_backend_common::kv_publisher` (`worker_query_endpoint.rs`). The stream item both ends exchange, `indexer::WorkerKvQueryReply`, stays here.
- Metric names and labels, event-plane subjects and the serialized messages defined here are contracts with workers, other routers and dashboards. A refactor must not change them.
- Features: `ckf-diagnostics` (snapshots of the worker query client; `dynamo-pool-relay` forwards it) and `testing` (fixtures and test-only handles that `dynamo-llm`'s tests reuse).
- Some ZMQ, event-plane and replica-sync tests bind local ports and can fail in a sandbox or in a full parallel run. Rerun a failing one alone before treating it as a regression.
- Check: `cargo test -p dynamo-sync`, `cargo check -p dynamo-sync --all-targets --features ckf-diagnostics`, and `cargo tree -p dynamo-sync | grep dynamo-llm` must print nothing.
