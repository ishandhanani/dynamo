# lib/kv-state-agent

`dynamo-kv-state-agent` is the KV state agent: code that runs outside the engine, turns an engine's raw KV events into router events and keeps the local index a router recovers from. `KvStateAgent` (`state_agent.rs`) owns exactly one stable DP slot: one recovery index, one event publisher and one outbound cursor. `KvStateAgentHost` (`state_agent_host.rs`) multiplexes these per-slot agents on one runtime; it is the standalone `python -m dynamo.kv_state_agent` process. `KvStateAttachmentOwner` (`attachment_owner.rs`) runs inside a worker process (the Python vLLM and SGLang backends) and holds the lease-owned attachment intents that bind the worker's engine to a host.

- Depends on (Dynamo crates): `dynamo-backend-common` (the stages of the KV event publisher the agent shares: `kv_publisher::{batching, dedup, metrics, sinks, zmq_listener}`), `dynamo-sync` (`direct_zmq_sub_pool`, `membership::kv_state_agent`, and the worker query endpoint in `indexer`), `dynamo-runtime`, `dynamo-kv-events`, `dynamo-kv-indexer` and `dynamo-router-protocol`. Tests also use `dynamo-kv-hashing` and the `testing` feature of `dynamo-sync` (`KvStateAgentStatusCell::snapshot`).
- Must not depend on: `dynamo-llm` or any crate above `dynamo-backend-common`. `dynamo-backend-common` cannot depend on this crate, and no sidecar and no mocker server links it: `cargo tree -e normal -i dynamo-kv-state-agent -p dynamo-vllm-sidecar` must find nothing.
- The Python bindings are the only caller (`rust/llm/kv_state_agent.rs`: `KvStateAgentHost` and `KvStateAttachmentOwner`). `attachment_owner.rs` uses neither the agent nor the host; it shares only the vocabulary in `dynamo_sync::membership::kv_state_agent` with them.
- Read [`lib/backend-common/src/kv_publisher/AGENTS.md`](../backend-common/src/kv_publisher/AGENTS.md) before changing the agent: it states which processing the agent shares with the legacy publisher and which differences are intentional.
- Slot handling, ZMQ subscription and recovery behaviour, dedup, batching, event ordering, topics, advertisement and wire formats, metric names and labels, log message text and env vars are contracts with routers, workers and dashboards. A refactor must not change them.
- Log targets are `dynamo_kv_state_agent::{state_agent, state_agent_host, attachment_owner}` (they were `dynamo_backend_common::kv_publisher::{state_agent, state_agent_host, attachment_owner}`). `DYN_LOG=dynamo_kv_state_agent=debug` shows the agent's lines.
- Check: `cargo test -p dynamo-kv-state-agent`, and `cargo tree -p dynamo-kv-state-agent | grep 'dynamo-llm '` must print nothing.
