# lib/discovery

`dynamo-discovery` is the frontend's model catalog. `ModelWatcher` (`watcher`) follows worker registrations and admits them into WorkerSets through `ModelDiscoveryController` (`controller`); for each WorkerSet it builds the routed pipeline (`pipeline`: preprocessor, migration, backend, encode and prefill hops, `RoutingHost`) and the routers it needs; `ModelManager` (`model_manager`) holds the resulting `Model`s (`model`) and `WorkerSet`s (`worker_set`), their engines, routers and LoRA state, and answers the frontend's lookups. Read [`src/AGENTS.md`](src/AGENTS.md) for the WorkerSet admission and succession contract before changing admission, construction or readiness.

- Also here, because the catalog builds or starts them: the HiCache shared KV cache client (`shared_cache`), the router's scheduler-load publisher (`scheduler_load`), the frontend's LoRA allocation gauges and the load-estimator event subscription (`lora`), and the in-process engines and adapters a catalog can hold without a routed pipeline (`engines`: the echo engines, `StreamingEngine`, `StreamingEngineAdapter`).
- Depends on (Dynamo crates): `dynamo-router-host` (the routers it builds), `dynamo-sync` (load context, runtime-config watch, replica sync), `dynamo-preprocessor`, `dynamo-frontend-protocols`, `dynamo-model-card`, `dynamo-lora`, `dynamo-runtime`; the router crates `dynamo-kv-router`, `dynamo-scheduler`, `dynamo-worker-selection`, `dynamo-slot-tracker`, `dynamo-kv-indexer`, `dynamo-kv-hashing`, `dynamo-kv-hints`, `dynamo-kv-events` and `dynamo-router-protocol`; `dynamo-http-server` (the request metrics handle `Migration` takes, and the model view of the frontend load frame); the published `dynamo-protocols`, `dynamo-decisions`, `dynamo-renderer` and `dynamo-tokenizers`.
- Must not depend on: `dynamo-llm`, `dynamo-pool-relay`, or any crate above them. The frontend (`dynamo-llm`: HTTP, gRPC, entrypoint) calls into this crate. What the router host needs from the catalog is passed down as `PrefillEndpointProvider` and `SchedulerLoadPublisher`.
- Hosts import this crate directly; `dynamo-llm` does not re-export it.
- A refactor must not change the discovery watch and registration order, WorkerSet admission and succession, readiness evaluation, router construction and configuration, or the pipeline's stage order. Metric names and labels (the `dynamo_frontend_lora_*` gauges are defined here), log message text and env vars are contracts.
- Log targets are `dynamo_discovery::...`. `DYN_LOG=dynamo_discovery=debug` shows the watcher, controller and model manager lines; `dynamo_discovery::shared_cache` is the HiCache client.
- Some tests start an in-memory distributed runtime, bind local ports, or re-run themselves in a child process; rerun a failing one alone before treating it as a regression.
- Check: `cargo test -p dynamo-discovery`, `cargo check -p dynamo-discovery --all-targets`, and `cargo tree -p dynamo-discovery | grep dynamo-llm` must print nothing.
